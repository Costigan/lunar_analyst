3. Use Spatialite as the project database.  Geotiffs, directories of Geotiffs and GeoPackages are formats for importing and exporting data.

Analysis will be scenario-based.

Each scenario will have a primary Digital Elevation Map (DEM).
This is called ElevationMap in C#.  You need to create a class for python.
This DEM provides coordinate system for the analysis, the rectangular area bounds for the analysis, and the pixel resolution for the analysis.
The scenario will also contain products imported from outside or derived using the tools in this project.
Many of the products will be geotiff files.  These should be stored in the filesystem with SpatiaLite keeping track of where they are.
Files associated with a single scenario must be in a single directory.
Files containing a given kind of data should be in their own subdirectories.

We can work on what 'kind of data' means here, and how to cluster similar files together.
For now, these are the kinds I know about
1. The DEM and products derived directly from the DEM like slope, roughness, aspect, 
2. Products related to lighting. This includes a directory containing horizon data calculated by new_horizon.  There will also be time-series lightmaps, which are directories of geotiff light map (or lightmap) images with timestamps in their names.   A light map is a byte geotiff whose values represent full shadow (0), full sun (255) and values in between, interpolated linearly.  There can also be individual gdal products that give the amount of time a each pixel is in sun over a time interval and so on.  Metadata for these products and their location in the filesystem needs to be tracked in SpatiaLite.
