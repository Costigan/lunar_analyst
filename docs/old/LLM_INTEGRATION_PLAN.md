# LLM Integration Plan (Option 1)

## 1. Scope

Implement LLM support in Lunar Analyst using a FastAPI-native assistant gateway plus MCP integration.

Required outcomes:
- One assistant that can both chat and execute tool actions.
- Prose commands can trigger Lunar Analyst capabilities.
- Assistant can describe Lunar Analyst capabilities.
- Assistant can describe products (GeoTIFFs, plots, tables) generated by Lunar Analyst or scripts.
- New request input panel in web UI.
- New assistant response panel in web UI.
- Lunar Analyst exposes capabilities through MCP for external clients.
- Local model support: Ollama and Python subprocess.
- Remote model support: OpenAI, Anthropic, Google, and compatible providers.
- Remote token caching enabled by default where provider/model supports it.
- Conversation history persisted to disk, resumable, with context compaction.

Out of scope for this plan:
- Marimo fork/patch for built-in AI panel internals.
- New native (.NET) compute contracts outside existing `JobHandlers` model.
- Packaging/deployment rewrites (Tauri bundling changes handled later).

## 2. Architecture Decision

Use a single FastAPI control-plane implementation for assistant orchestration:
- Assistant orchestration, policy, and persistence in backend services.
- Built-in tool catalog exposed as MCP tools.
- External MCP clients can connect to Lunar Analyst MCP server.
- Built-in assistant can also connect to external MCP servers (optional extension path).
- UI talks only to FastAPI APIs/WS.

This preserves architecture invariants in `AGENTS.md`:
- FastAPI remains authoritative.
- No duplicate parallel compute contract layers.
- Long-running work still uses existing job orchestration.
- Scenario/file safety stays path-normalized and root-allowlisted.

## 3. High-Level Data Flow

1. User enters prose in Assistant Input panel.
2. Frontend posts turn request to FastAPI assistant API.
3. Assistant runtime resolves context (session history + scenario context + summaries).
4. Model proposes answer and/or tool calls.
5. Mutating calls require confirmation by policy.
6. Tool calls execute through existing service container and job routes.
7. Assistant streams deltas/events to Assistant Response panel.
8. Turn, tool calls, confirmations, summaries are persisted in SQLite.
9. Session can be resumed later by `session_id`.

### 4.1 New REST Endpoints (Assistant)

Add in new router: `backend/api/routers/assistant.py`.

- `POST /api/v1/assistant/sessions`
  - request: `CreateAssistantSessionRequest`
  - response: `AssistantSession`
- `GET /api/v1/assistant/sessions`
  - response: `ListAssistantSessionsResponse`
- `GET /api/v1/assistant/sessions/{session_id}`
  - response: `AssistantSessionDetailResponse`
- `POST /api/v1/assistant/sessions/{session_id}/turns`
  - request: `CreateAssistantTurnRequest`
  - response: `CreateAssistantTurnResponse`
- `GET /api/v1/assistant/sessions/{session_id}/messages`
  - response: `ListAssistantMessagesResponse`
- `POST /api/v1/assistant/sessions/{session_id}/confirmations/{confirmation_id}`
  - request: `AssistantConfirmationDecisionRequest`
  - response: `AssistantConfirmationDecisionResponse`
- `PATCH /api/v1/assistant/sessions/{session_id}/policy`
  - request: `UpdateAssistantPolicyRequest`
  - response: `AssistantPolicy`
- `POST /api/v1/assistant/sessions/{session_id}:compact`
  - request: `CompactAssistantSessionRequest`
  - response: `CompactAssistantSessionResponse`
- `GET /api/v1/assistant/providers`
  - response: `AssistantProviderCatalogResponse`

### 4.3 MCP Contract

Add MCP server module: `backend/mcp/server.py`.

MCP tools map to existing service-layer actions and read helpers.
Initial tool namespaces:
- `scenario.*`
- `product.*`
- `layer.*`
- `job.*`
- `map.*`
- `artifact.describe_*`

External MCP transport support:
- `stdio` runner: `backend/tools/run_mcp_server.py`

### 4.4 Confirmation Policy Contract

Action categories:
- `launch_job`
- `import_file`
- `move_path`
- `update_layer_state`
- `delete_artifact`
- `write_notebook`

Decision modes:
- `allow_once`
- `always_allow_action_type` (session-scoped)
- `deny_once`

Policy persisted per session and mutable through API.

## 9. Risks and Controls

- Provider/API drift:
  - Control: adapter-level feature flags and graceful fallback.
- Unsafe tool execution:
  - Control: confirmation policy defaults to require confirmation for mutating categories.
- GPU contention with lunar compute:
  - Control: model routing policy, fallback to smaller local model or remote provider.
- Context growth and cost:
  - Control: compaction checkpoints + stable-prefix cache strategy.
- External MCP attack surface:
  - Control: HTTP auth token, allowlists, optional stdio-only mode.

## 10. Rollback Strategy

- Feature flag all assistant routes under `[backend.llm].enabled`.
- Feature flag MCP transports separately (`http_enabled`, `stdio_enabled`).
- If remote providers fail, keep local provider path active.
- If token caching issues occur, disable per provider while preserving provider availability.
- If mutating behavior is risky, force confirmation for all mutation actions.
