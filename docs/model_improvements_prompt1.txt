• Use a hybrid turn pipeline with sentence/segment-level execution, not all-or-nothing routing.

  1. Segment the prompt into prompt segments

  - Split by sentence and conjunction boundaries (and, then, also, but), but keep dependent clauses together.
  - Build segments[] with original text offsets so order is preserved.

  2. Classify each segment

  - deterministic_candidate: matches router rule with high confidence and no complexity guard hit.
  - llm_required: analysis/explanation/open-ended planning/ambiguous instruction.
  - blocked: safety or missing required inputs.

  3. Build one execution plan for the whole turn

  - Preserve segment order.
  - Mark each segment with execution_mode (deterministic or llm).
  - Attach dependencies (segment 3 depends on output artifact from segment 1).

  4. Execute deterministic segments first (in order)

  - Run router action specs and tool calls.
  - Apply normal confirmation gates for mutating actions.
  - Store structured outputs in a turn_state object (new layers, stats, files, errors).

  5. Hand only unresolved remainder to the LLM

  - Pass:
      - Original user prompt
      - Unhandled segments text
      - Compact summary of deterministic outcomes from turn_state
      - Relevant tool schemas (focused via tools.search/tools.describe)
  - Instruct model to continue from current state, not re-do completed actions.

  6. Merge into one final response

  - Chronological output:
      - Actions completed deterministically
      - LLM-driven analysis/recommendations
      - Any failures/questions requiring user input
  - Include per-segment status (done, failed, needs_clarification).

  7. Failure policy

  - If a deterministic segment fails:
      - Continue with independent later segments.
      - For dependent segments, mark blocked and expose a concrete recovery step.
  - Never silently fallback a failed deterministic action to model improvisation for mutating operations.

  8. Guardrails to avoid bad splits

  - Don’t deterministically capture segments containing conditional/complex logic (if, unless, only if, optimization/comparison requests).
  - Send those segments to LLM or deterministic sub-agent with strict tool allowlist.

  Example:
  “Switch to Shackleton scenario. Turn on slope and hillshade. Then suggest the top 3 candidate landing zones with rationale.”

  - Seg1/2 deterministic (scenario switch, layer visibility)
  - Seg3 LLM (scientific reasoning)
  - LLM receives updated state (active scenario + visible layers) and returns analysis only.
